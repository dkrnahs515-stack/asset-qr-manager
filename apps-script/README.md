# Google Sheets 연동 모바일 전수조사 MVP

이 폴더는 기존 Firebase 앱과 별개로 운영되는 Google Sheets 기반 모바일 전수조사 구현입니다.

## 기준 Google Sheet

- Spreadsheet ID: `1R5WjwpXtsJwQfIvNnQ_D5PLD6TTLXqTlQ7CSjbUa274`
- 필수 탭: `비품마스터`, `위치마스터`, `오류검토`, `전수조사세션`, `전수조사기록`, `변경이력`

## 파일

- `Core.js`: 세션 ID, 조사기록 생성, 대표위치/진행률 계산 등 순수 로직. Node 테스트와 Apps Script 양쪽에서 사용한다.
- `Code.gs`: Google Sheets 읽기/쓰기 및 Web App 서버 함수.
- `Index.html`: React 18 모바일 UI.
- `appsscript.json`: Apps Script 매니페스트.

## Apps Script 편집기에서 배포

1. `script.google.com`에서 새 독립형 Apps Script 프로젝트를 만든다.
2. 기본 `Code.gs`를 저장소의 `Code.gs` 내용으로 교체한다.
3. 코드 파일 `Core.gs`를 새로 만들고 저장소의 `Core.js` 내용을 그대로 붙여 넣는다.
4. HTML 파일 `Index`를 만들고 `Index.html` 내용을 붙여 넣는다.
5. 프로젝트 설정에서 매니페스트 파일 표시를 켠 뒤 `appsscript.json` 내용을 적용한다.
6. `배포 > 새 배포 > 웹 앱`으로 배포한다.
7. 실행 계정과 접근 범위는 기관의 Google 계정 정책에 맞게 제한한다.
8. 발급된 HTTPS 웹 앱 주소를 스마트폰에서 연다.

## 첫 수용 테스트

### 0. 사전 확인
- `전수조사세션`과 `전수조사기록`에 테스트 중인 활성 세션이 없어야 한다.
- 현재 `비품마스터`의 유효한 영구 시스템 ID 개수를 확인한다. 현재 설계 기준은 842개다.

### 1. 세션 생성
1. 스마트폰에서 웹 앱을 연다.
2. 조사자 이름을 입력한다.
3. `전수조사 시작`을 누른다.
4. `전수조사세션`에 `INV-2026-001` 형식의 행이 1개 생성되는지 확인한다.
5. `전수조사기록`에 등록 비품 수와 동일한 행이 생성되는지 확인한다.
6. 모든 생성 행의 `조사결과=미확인`, `실물확인여부=N`, `관리자검토상태=미검토`, `마스터반영여부=N`인지 확인한다.
7. `확인위치코드/층/공간명`은 공란이어야 한다.

### 2. 공간 이동
1. 층을 누른다.
2. 해당 층 공간 카드의 전체/완료/미확인 수가 나타나는지 확인한다.
3. 공간을 누르면 기존 위치 기준 비품 목록이 나타나는지 확인한다.
4. `미확인만` 필터가 기본값인지 확인한다.

### 3. 정상 확인
1. 미확인 비품을 누른다.
2. 상세 화면에서 품명, 번호, 규격, 등록 위치를 확인한다.
3. `정상 · 실물 확인`을 누른다.
4. 해당 `전수조사기록` 행이 아래처럼 바뀌는지 확인한다.
   - `조사결과=정상`
   - `실물확인여부=Y`
   - `위치일치여부=Y`
   - `라벨상태=정상`
   - 확인 위치 = 기존 위치
   - 조사자/최초조사일시/최종수정일시 기록
   - 수정버전 1 증가
5. `변경이력`에 `작업유형=정상확인` 행이 1개 추가되는지 확인한다.
6. 모바일 화면에서 미확인 수가 1 감소하고 완료 수가 1 증가하는지 확인한다.
