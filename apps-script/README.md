# Google Sheets 연동 모바일 전수조사 MVP

이 폴더는 기존 Firebase 앱과 별개로 운영되는 Google Sheets 기반 모바일 전수조사 구현입니다.

## 기준 Google Sheet

- Spreadsheet ID: `1R5WjwpXtsJwQfIvNnQ_D5PLD6TTLXqTlQ7CSjbUa274`
- 필수 탭: `비품마스터`, `위치마스터`, `오류검토`, `전수조사세션`, `전수조사기록`, `변경이력`
- 2026-08-19 배포 전 확인 상태: `전수조사세션` 및 `전수조사기록`은 헤더만 있고 데이터 행은 0건

## Apps Script에 복사할 파일

Apps Script 편집기에서는 아래 이름으로 만든다.

| 저장소 파일 | Apps Script 파일명 | 종류 |
|---|---|---|
| `Code.gs` | `Code.gs` | 스크립트 |
| `Core.js` | `Core.gs` | 스크립트 |
| `Inspection.gs` | `Inspection.gs` | 스크립트 |
| `Index.html` | `Index.html` | HTML |
| `appsscript.json` | `appsscript.json` | 매니페스트 |

`Core.js`는 저장소에서 Node 테스트가 가능하도록 `.js` 확장자를 사용하지만 Apps Script 편집기에서는 `Core.gs`로 만든다.

## 1. Google Sheet에서 Apps Script 프로젝트 만들기

1. 기준 Google Sheet `강서청소년회관 QR 비품관리 대장 (이전초안)`을 연다.
2. 상단 메뉴에서 `확장 프로그램 > Apps Script`를 누른다.
3. Apps Script 편집기가 새 탭에서 열리면 프로젝트명을 `강서청소년회관 비품 전수조사`로 변경한다.
4. 기본으로 생성된 `Code.gs`는 삭제하지 말고 내용을 전부 지운 뒤 저장소 `apps-script/Code.gs` 내용으로 교체한다.

## 2. Core.gs 추가

1. 왼쪽 `파일` 영역의 `+` 버튼을 누른다.
2. `스크립트`를 선택한다.
3. 이름을 `Core`로 입력한다. 편집기에는 `Core.gs`로 표시된다.
4. 저장소 `apps-script/Core.js` 내용을 처음부터 끝까지 붙여 넣는다.
5. 저장한다.

## 3. Inspection.gs 추가

1. 다시 `파일 + > 스크립트`를 누른다.
2. 이름을 `Inspection`으로 입력한다.
3. 저장소 `apps-script/Inspection.gs` 전체를 붙여 넣는다.
4. 저장한다.

이 파일이 다음 기능을 담당한다.

- 위치 다름
- 상태 이상
- 미발견
- Undo
- 모바일 위치 선택 목록

## 4. Index.html 추가

1. `파일 + > HTML`을 누른다.
2. 이름을 `Index`로 입력한다.
3. 생성된 기본 HTML을 전부 지운다.
4. 저장소 `apps-script/Index.html` 전체를 붙여 넣는다.
5. 저장한다.

## 5. appsscript.json 적용

1. 왼쪽 메뉴 아래의 `프로젝트 설정` 톱니바퀴를 누른다.
2. `편집기에 appsscript.json 매니페스트 파일 표시` 옵션을 켠다.
3. 파일 목록으로 돌아가 `appsscript.json`을 연다.
4. 기존 내용을 저장소의 `apps-script/appsscript.json` 내용으로 교체한다.
5. 저장한다.

현재 매니페스트는 시간대를 `Asia/Seoul`, 런타임을 V8로 지정하고 Google Sheets 권한만 요청한다.

## 6. 저장 여부 확인

Apps Script 왼쪽 파일 목록이 아래와 같아야 한다.

```text
Code.gs
Core.gs
Inspection.gs
Index.html
appsscript.json
```

각 파일 탭에 저장되지 않은 변경 표시가 없는지 확인한다.

## 7. 먼저 테스트 배포(`/dev`)하기

정식 배포 전에 개발용 URL로 확인한다.

1. 오른쪽 위 `배포`를 누른다.
2. `테스트 배포`를 선택한다.
3. 배포 유형에서 `웹 앱`을 선택한다.
4. 표시되는 웹 앱 URL을 복사한다.
5. 주소가 `/dev`로 끝나는지 확인한다.
6. 새 브라우저 탭에서 연다.

`/dev` URL은 스크립트 편집 권한이 있는 사용자만 접근할 수 있고, 저장된 최신 코드를 바로 사용하므로 첫 검증에 적합하다.

## 8. 권한 승인

처음 Spreadsheet 서비스가 실행될 때 Google 권한 요청이 나타날 수 있다.

1. 프로젝트를 만든 Google 계정을 선택한다.
2. 이 스크립트가 Google Sheets를 보고 수정할 수 있도록 요청된 권한 내용을 확인한다.
3. 본인이 만든 프로젝트와 기준 Sheet가 맞는지 확인한 뒤 허용한다.
4. 권한 승인 후 `/dev` 웹앱을 새로고침한다.

## 9. 첫 화면 수용 기준

웹앱이 정상적으로 열리면 다음이 보여야 한다.

- 제목: `비품 전수조사`
- 우측 상단: `● 온라인`
- `새 전수조사 시작`
- `조사자 이름` 입력칸
- `전수조사 시작` 버튼

이 시점에는 아직 Google Sheet에 세션이나 전수조사기록이 생성되면 안 된다.

## 10. 첫 실기 테스트 — 842개 세션 생성

현재 기준 시트는 활성 세션/조사기록이 0건이므로 처음 한 번만 수행한다.

1. 조사자 이름을 입력한다.
2. `전수조사 시작`을 한 번만 누른다.
3. 화면이 층 선택 화면으로 이동하는지 확인한다.
4. 모바일 화면 전체 진행률이 `0 / 842`, `0%`, `미확인 842개`인지 확인한다.
5. Google Sheet의 `전수조사세션`을 연다.
6. 2행에 새 세션이 한 건 생성되었는지 확인한다.
7. `기준비품수=842`, `완료건수=0`, `미확인건수=842`, `세션상태=진행중`인지 확인한다.
8. `전수조사기록`을 연다.
9. 헤더 아래 842행이 생성되어 총 마지막 행이 843행인지 확인한다.
10. 첫 기록과 마지막 기록의 기록ID가 같은 세션 아래 `...-0001`부터 `...-0842`까지 이어지는지 확인한다.
11. 생성된 모든 기록은 최초 상태가 `조사결과=미확인`, `실물확인여부=N`, `관리자검토상태=미검토`, `마스터반영여부=N`이어야 한다.
12. `확인위치코드/확인층/확인공간명`은 최초에는 공란이어야 한다.

## 11. 첫 현장 사이클 — 정상 확인

1. 웹앱에서 층 하나를 선택한다.
2. 공간 하나를 선택한다.
3. `미확인만` 필터가 기본 선택인지 확인한다.
4. 실제 확인 가능한 비품 한 개를 누른다.
5. 품명, New/Old 번호, 규격, 등록 위치가 실물과 일치하는지 확인한다.
6. `✓ 정상 · 실물 확인`을 누른다.
7. 목록으로 돌아오고 하단에 `↶ 취소` 바가 표시되는지 확인한다.
8. 해당 비품은 `전수조사기록`에서 `조사결과=정상`, `실물확인여부=Y`, `위치일치여부=Y`, `라벨상태=정상`으로 바뀌어야 한다.
9. `변경이력`에 `작업유형=정상확인` 행이 추가되어야 한다.
10. 전체 진행률은 `1 / 842`가 되고 미확인 수는 `841`이 되어야 한다.

## 12. Undo 테스트

정상 확인 직후 표시된 `↶ 취소`를 누른다.

예상 결과:

- 해당 비품의 `조사결과`가 다시 `미확인`으로 복원
- 실물/위치 확인값도 작업 전 값으로 복원
- 전체 진행률 `0 / 842`, 미확인 `842`
- 원래 변경이력의 `취소여부=Y`
- 새 `작업유형=작업취소` 이력 추가
- 취소 이력의 `이전변경ID`가 취소한 변경ID를 가리킴
- 삭제되는 이력은 없음

## 13. 위치 다름 테스트

실제로 위치가 다른 비품 또는 테스트하기 쉬운 비품으로 수행한다.

1. 상세 화면에서 `📍 위치 다름`을 누른다.
2. 발견한 실제 공간을 선택한다.
3. 필요하면 메모를 입력한다.
4. `위치변경 저장`을 누른다.
5. 기록이 `조사결과=위치변경`, `실물확인여부=Y`, `위치일치여부=N`으로 저장되는지 확인한다.
6. `확인위치코드/확인층/확인공간명`에 선택한 위치가 저장되는지 확인한다.
7. 변경이력에 `작업유형=위치변경`이 추가되는지 확인한다.

대표위치가 같은 공간을 위치변경으로 선택하면 서버가 저장을 거부하도록 되어 있다.

## 14. 상태 이상 테스트

1. 상세 화면에서 `⚠ 상태 이상`을 누른다.
2. `파손 / 고장 / 수리필요 / 사용불가 / 불용검토 / 라벨없음 / 라벨훼손 / 번호불일치 / 정보수정필요 / 기타` 중 하나를 선택한다.
3. 실물 확인 위치를 확인한다.
4. 필요하면 메모를 입력한다.
5. `상태이상 저장`을 누른다.
6. `조사결과=상태이상`, `이상유형=선택값`, `실물확인여부=Y`가 저장되는지 확인한다.
7. 라벨 이상 유형을 선택하면 `라벨상태`도 함께 바뀌는지 확인한다.

## 15. 미발견 테스트

1. 공간을 충분히 확인한 뒤 찾지 못한 비품을 연다.
2. `🔎 못 찾음`을 누른다.
3. 안내문에서 `분실 확정이 아님`을 확인한다.
4. 필요하면 메모를 입력한다.
5. `미발견으로 기록`을 누른다.
6. `조사결과=미발견`, `실물확인여부=N`으로 저장되는지 확인한다.
7. 확인 위치는 공란이어야 한다.
8. 비품마스터의 물품상태를 즉시 `분실`로 바꾸면 안 된다.

## 16. 정식 웹 앱 배포(`/exec`)

`/dev`에서 위 첫 사이클이 확인된 뒤 진행한다.

1. 오른쪽 위 `배포 > 새 배포`를 누른다.
2. `유형 선택` 옆 설정 아이콘에서 `웹 앱`을 선택한다.
3. 설명에 예: `모바일 전수조사 MVP 2026-08-19`를 입력한다.
4. 첫 운영 테스트는 `실행 사용자: 나`를 권장한다.
5. `액세스 권한`은 기관 정책에 맞게 고른다. 개인 테스트 단계에서는 본인만 접근하도록 제한하는 것이 가장 안전하다.
6. `배포`를 누른다.
7. 필요하면 권한을 승인한다.
8. `/exec`로 끝나는 웹 앱 URL을 복사한다.
9. 스마트폰 홈 화면에 바로가기를 추가해 현장 테스트에 사용한다.

다른 직원이 사용할 때는 Google Workspace 정책과 기관 계정 범위를 확인한 후 액세스 범위를 확대한다.
