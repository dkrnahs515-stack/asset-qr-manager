# 모바일 비품 전수조사 MVP 설계

## 목표
강서청소년회관 비품관리 Google Sheet를 기준 DB로 사용해 스마트폰에서 전수조사를 시작하고, 층/공간별 비품을 확인하며, 정상 확인 1회 터치로 조사기록과 변경이력을 남기고 진행률을 갱신하는 첫 완전한 사이클을 구현한다.

## 기준 데이터
- Spreadsheet ID: `1R5WjwpXtsJwQfIvNnQ_D5PLD6TTLXqTlQ7CSjbUa274`
- 비품마스터: 현재 842개, 헤더 1행 + 데이터 842행
- 위치마스터: 53개 위치
- 신규 조사 DB: `전수조사세션`, `전수조사기록`, `사진`, `변경이력`
- 위치마스터 추가 필드: `조사표시여부`, `모바일정렬순서`, `대표위치코드`

## 기술 구조
1. 모바일 UI는 React 18을 사용한다.
2. 첫 MVP는 별도 Node 서버 없이 Google Apps Script HTML Service에서 React UI를 제공한다.
3. 브라우저에서 Apps Script 서버 호출은 `google.script.run`으로 한다.
4. Google Sheet 읽기/쓰기는 `Code.gs`가 담당한다.
5. 세션 ID 생성, 기록 행 생성, 대표위치 정규화, 진행률 집계 같은 순수 계산은 `Core.js`에 분리해 Node 테스트가 가능하게 한다.
6. 기존 Firebase 정적 앱은 삭제하거나 수정하지 않고 `apps-script/` 경로에 새 구현을 병행한다.

## 1차 MVP 범위
- 활성 세션 조회
- 전수조사 시작
- 842개 비품을 전수조사기록에 일괄 스냅샷 생성
- 층별 진행률 조회
- 층 선택 후 공간별 진행률 조회
- 공간 선택 후 미확인/전체 비품 목록 조회
- 비품 상세 확인
- `정상 · 실물 확인` 처리
- 처리 즉시 전수조사기록 갱신
- 변경이력 1행 추가
- 세션 집계값 및 진행률 갱신
- 최근 작업을 되돌릴 수 있도록 작업 UUID와 변경 로그 기반을 남김

## 1차 MVP에서 제외
- QR 카메라 스캔
- 사진 업로드
- 위치변경 상세 처리
- 상태이상 상세 처리
- 미등록 비품 등록
- IndexedDB 오프라인 큐
- 관리자 승인/반려

이 항목들은 DB 구조와 API 인터페이스를 깨지 않고 다음 단계에서 추가한다.

## 세션 생성 규칙
1. `전수조사세션`에서 상태가 `준비` 또는 `진행중`인 세션이 있으면 새 세션을 만들지 않고 기존 세션을 반환한다.
2. 활성 세션이 없으면 `INV-YYYY-NNN` 형식으로 세션 ID를 만든다.
3. 비품마스터의 유효한 `영구 시스템 ID` 행을 한 번에 읽는다.
4. 세션 생성 시점의 비품정보를 `전수조사기록`에 스냅샷으로 저장한다.
5. 기록 ID는 `INVR-YYYY-NNN-0001` 형식을 사용한다.
6. 초기 조사결과는 모두 `미확인`, 실물확인여부 `N`, 관리자검토상태 `미검토`, 마스터반영여부 `N`, 수정버전 `0`이다.
7. `확인위치코드/층/공간명`은 실제 확인 전까지 공란으로 둔다.
8. 842행은 `appendRow` 반복이 아니라 단일 `setValues()`로 일괄 기록한다.

## 진행률 정의
- 등록 비품만 분모에 포함한다.
- `미등록발견`은 별도 수치이며 기존 조사 대상 분모를 늘리지 않는다.
- 완료 상태: `정상`, `위치변경`, `상태이상`, `미발견`, `보류`.
- 미완료 상태: `미확인`.
- 공간 진행률은 비품의 `기존위치코드`를 위치마스터의 `대표위치코드`로 정규화한 뒤 계산한다.
- `조사표시여부=검토` 위치도 조사 대상에서 제외하지 않고 별도 검토 그룹으로 노출한다.
- 전체 진행률 = `(기준비품수 - 미확인건수) / 기준비품수 * 100`.

## 정상 확인 동작
입력: `sessionId`, `recordId`, `inspector`, `actionUuid`.

처리:
1. `LockService`로 동시 수정을 직렬화한다.
2. 변경이력에 동일 `actionUuid`가 이미 존재하면 중복 처리하지 않고 현재 상태를 반환한다.
3. 대상 기록이 해당 세션에 속하는지 검증한다.
4. 기존 조사결과가 `미확인`일 때 `정상`으로 변경한다.
5. `실물확인여부=Y`, `위치일치여부=Y`, `라벨상태=정상`을 기록한다.
6. 확인위치는 기존 위치와 동일하게 기록한다.
7. 조사자, 최초조사일시, 최종수정일시, 수정버전, 최근작업UUID를 갱신한다.
8. 변경이력에 `정상확인` 행을 추가한다.
9. 세션 집계값을 이전 결과→새 결과 델타로 갱신한다.

## 모바일 화면
- 홈: 활성 세션, 전체 진행률, 조사 이어하기/시작
- 층 선택: 지하1층, 1층, 2층, 3층, 옥상, 외부, 검토 필요 그룹
- 공간 선택: 공간별 완료/전체/미확인 표시
- 공간 조사: 검색, 미확인/전체 토글, 비품 카드
- 비품 상세: 품명, 번호, 규격, 등록위치, 큰 `정상 · 실물 확인` 버튼

한 손 조작을 우선하며 정상 확인은 추가 확인창 없이 즉시 저장하고 성공 토스트 후 목록으로 복귀한다.

## 오류 처리
- 세션 시작 중 중복 요청은 LockService와 활성 세션 검사로 차단한다.
- 정상 확인 API는 actionUuid 기반으로 멱등 처리한다.
- 서버 오류 시 React는 낙관적 변경을 확정하지 않고 오류 메시지를 보여준다.
- 데이터 행/헤더가 예상 구조와 다르면 명확한 오류를 반환한다.

## 테스트 기준
순수 Core 함수는 Node 내장 테스트러너로 검증한다.
- 세션 ID 증가 규칙
- 842행 레코드 생성 규칙
- 초기 상태값
- 대표위치 정규화
- 전체/층/공간 진행률 집계
- `미등록발견` 분모 제외
- 상태 전환 델타 계산

Apps Script I/O는 Core 테스트 통과 후 실제 Google Sheet 사본 또는 테스트 세션에서 검증한다.
