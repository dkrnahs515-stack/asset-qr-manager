# QR 대량발급 배치·복구 설계

## 목적

TEST에서 검증한 QR 개별 발급 로직을 827개 운영 대상에 확대하되, Apps Script 실행 제한이나 일시 오류가 발생해도 이미 처리한 비품을 다시 발급하지 않고 마지막 체크포인트부터 재개한다.

## 실제 TEST 데이터 기준

- `비품마스터`: 842개, 영구 시스템 ID 842개 모두 유일
- `라벨출력`: 827개, 영구 시스템 ID 827개 모두 유일
- 차이 15개: 모두 `물품상태=불용예정`, `사용여부=확인필요`
- `라벨출력`에만 존재하는 비품: 0개
- `QR발급관리`: 30행, 활성 QR 29개, 활성 QR 시스템 ID 중복 0개
- 과거 중지 이력을 포함해 동일 시스템 ID가 2행인 비품은 `GSYC-000003` 1개이며 활성 행은 1개라 정상 이력이다.

따라서 대량발급 대상은 총 등록수 842개가 아니라 현재 정책상 `사용여부=사용`인 827개다. 제외된 15개는 상태가 `사용`으로 승인되기 전까지 자동 발급하지 않는다.

## 안전 규칙

1. 미리보기는 시트를 변경하지 않는다.
2. 미리보기는 대상 목록과 활성 QR 상태로 결정되는 미리보기 fingerprint를 반환한다.
3. 배치 생성 시 미리보기 fingerprint를 다시 계산해 일치하지 않으면 생성하지 않는다.
4. 배치에는 시스템 ID·비품번호·사용여부만 포함한 대상 fingerprint를 저장한다. QR 생성 결과는 이 지문을 바꾸지 않는다.
5. 한 환경에는 완료되지 않은 대량발급 배치를 하나만 허용한다.
6. 실행당 최대 50개만 처리한다.
7. 이미 유효한 활성 QR이 있으면 새 키를 만들지 않고 재사용한다.
8. 개별 실패가 다른 항목의 처리를 막지 않으며 오류를 항목 행에 기록한다.
9. 실행이 체크포인트 저장 전에 중단돼도 재실행 시 활성 QR을 재사용하므로 중복 발급되지 않는다.
10. 실패 항목은 명시적 재시도 함수로만 다시 `대기` 상태가 된다.
11. 생성·실행·실패 재시도는 모두 Script Lock 안에서 수행한다.
12. 배치가 시작된 뒤 마스터 대상 fingerprint가 달라지면 실행을 중단하고 새 미리보기를 요구한다.
13. 50개 처리에서는 마스터와 QR 원장을 한 번씩 읽고 누적 변경을 일괄 기록한다.
14. 배치 행을 `생성중`으로 먼저 저장하고 항목 저장이 끝난 뒤 `준비`로 전환한다. 중단 시 같은 배치 ID로 생성을 재개한다.
15. 오래되거나 복구하지 않을 열린 배치는 삭제하지 않고 `취소` 상태로 닫아 감사 근거를 보존한다.
16. QR 원장과 마스터는 전체 범위를 재작성하지 않고 변경 셀과 새 행만 기록해 수식·추가 열·내부 빈 행을 보존한다.

## 저장 구조

### `QR대량발급배치`

배치별 환경, fingerprint, 배치 크기, 상태, 전체·성공·재사용·실패·미처리 수, 다음 처리 순번과 시각 정보를 한 행에 저장한다.

### `QR대량발급항목`

배치 생성 시 827개 대상 스냅샷을 처리 순번대로 저장한다. 각 행은 `대기`, `성공`, `재사용`, `실패` 중 하나의 처리 상태와 시도 횟수, 결과 QR, 오류 메시지를 가진다.

## 공개 Apps Script 함수

- `previewBulkQrIssuance()` — 읽기 전용 DRY RUN과 fingerprint 반환
- `createBulkQrIssuanceBatch(request)` — fingerprint 검증 후 배치·항목 스냅샷 생성
- `processBulkQrIssuanceBatch(request)` — 다음 대기 항목 최대 50개 처리
- `cancelBulkQrIssuanceBatch(request)` — 열린 배치를 삭제 없이 취소 상태로 종료
- `retryFailedBulkQrIssuance(request)` — 실패 항목을 대기로 되돌림
- `getBulkQrIssuanceStatus(batchId)` — 체크포인트와 집계 조회

Apps Script 편집기에서는 인자 없는 `stageBulkQrIssuancePreview()`, `createBulkQrIssuanceBatchFromStagedPreview()`, `processOpenBulkQrIssuanceBatch()`, `retryFailedOpenBulkQrIssuance()`, `cancelOpenBulkQrIssuanceBatch()`, `getOpenBulkQrIssuanceStatus()`를 사용한다.

## 완료 기준

- 827개 대상과 제외 15개가 DRY RUN에서 구분된다.
- 기존 활성 QR은 재사용으로 집계된다.
- 50개를 초과해 처리하지 않는다.
- 성공·재사용 항목은 재개 시 건너뛴다.
- 실패분만 명시적으로 재시도할 수 있다.
- fingerprint 불일치와 동시 열린 배치를 차단한다.
- 기존 자동 테스트를 포함한 전체 테스트가 통과한다.
